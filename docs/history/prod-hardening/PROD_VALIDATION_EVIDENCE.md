# Production Validation Evidence Report

**Date:** 2025-01-XX  
**Purpose:** Document the root cause of non-deterministic validation failures in production demos

---

## Executive Summary

The production demo's per-spec validation fails because it scans the **entire target repository** rather than only the files generated by the current run. This causes failures from pre-existing code that has nothing to do with the current workflow's output.

---

## Two Validation Pipelines

### Pipeline 1: In-Workflow Sandbox (✅ CORRECT)

**Location:** `src/integration_coworker/graph/nodes/generate_code_and_tests.py:520-600`

**How it collects artifacts:**
```python
# Line ~540: Builds sandbox_artifacts from python_artifacts (generated code only)
python_artifacts = [
    ArtifactFile(path=a.rel_path, content=a.content)
    for a in code_artifacts
    if a.language == "python"
]
sandbox_artifacts = python_artifacts + [
    ArtifactFile(path=a.rel_path, content=a.content)
    for a in code_artifacts
    if a.rel_path.startswith("tests/") and a.language == "python"
]
```

**Scope:** Only files in the current run's `code_artifacts` list  
**Result:** ✅ Deterministic, passes consistently

---

### Pipeline 2: Per-Spec Validation in Demo Script (❌ TOO BROAD)

**Location:** `scripts/demo-final-showcase.sh:1380-1430`

**How it collects artifacts:**
```python
# Line ~1388-1405: Scans ENTIRE target directory tree
src_dirs = [
    os.path.join(repo_root, "src", "integrations"),
    os.path.join(repo_root, "integrations"),
]
tests_dir = os.path.join(repo_root, "tests")

for search_dir in src_dirs:
    if os.path.exists(search_dir):
        for py_file in glob.glob(os.path.join(search_dir, "**", "*.py"), recursive=True):
            # Collects ALL .py files, not just generated ones!

                content = f.read()

```

**Scope:** ALL `.py` files in `src/integrations/**` and `tests/**`  
**Result:** ❌ Non-deterministic, fails when pre-existing files have issues

## Why In-Workflow Validation Passes

The in-workflow sandbox (`generate_code_and_tests.py`) builds artifacts from `code_artifacts`:

```python
# code_artifacts comes from the LLM code generation step
# It contains ONLY the files generated in THIS run
python_artifacts = [
    ArtifactFile(path=a.rel_path, content=a.content)
    for a in code_artifacts
    if a.language == "python"
]
```

This means:
- Fresh run → validates only freshly generated code
- No pollution from prior runs
- Deterministic results

## File Write Path (Where Manifest Should Be Generated)

**Location:** `src/integration_coworker/graph/nodes/apply_repo_integration_changes.py`

This node writes files to the target repository:

```python
# Line ~305-320: Iterates over code_artifacts and repo_changes
if has_code_artifacts:
    for artifact in state.code_artifacts:
        result = _apply_code_artifact(artifact, repo_root, backup_dir, is_dry_run, io)
        applied_changes.append(result)

if has_repo_changes:
    for change in state.repo_changes.changes:
        result = _apply_repo_change(change, repo_root, backup_dir, is_dry_run, io)
        applied_changes.append(result)
```

**Key insight:** `applied_changes` already contains the exact list of files written!

```python
# Line ~390: Stores in plan
state.plan["applied_changes"] = applied_changes
```

---

## Root Cause Summary

1. **Per-spec validation uses glob pattern** to scan entire target repo
2. **Target repo contains pre-existing files** from previous runs or manual additions
3. **Pre-existing files may have issues** (bare except, type errors, style violations)
4. **Validation fails on pre-existing issues** unrelated to current run's generated code

---

## Recommended Fix

Replace the glob-based artifact collection in per-spec validation with a **manifest-based approach**:

1. After `apply_repo_integration_changes`, write a manifest file listing generated files
2. Per-spec validation reads the manifest instead of globbing
3. Only files in the manifest are validated

This matches the behavior of in-workflow validation, making results deterministic.

See: `docs/PROD_VALIDATION_DESIGN.md` for implementation design.
