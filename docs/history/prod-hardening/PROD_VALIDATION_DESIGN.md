# Production Validation Design Document

**Date:** 2025-01-XX  
**Purpose:** Design scoped validation that only validates files generated in the current run

---

## Problem Statement

Per-spec validation in the production demo fails non-deterministically because it scans the entire target repository rather than only the files generated by the current run. Pre-existing files with issues (bare except, type errors) cause validation failures unrelated to the current workflow's output.

---

## Design Goals

| Goal | Priority | Description |
|------|----------|-------------|
| **Deterministic** | P0 | Same input → same validation result |
| **Scoped** | P0 | Only validate files from current run |
| **Isolated** | P1 | No dependence on target repo cleanliness |
| **Auditable** | P2 | Clear record of what was validated |
| **Minimal changes** | P2 | Don't refactor core workflow |

---

## Options Comparison

### Option A: Manifest File

**Approach:** Write a JSON manifest listing generated files, validation reads from manifest.

**Touch Points:**
1. `apply_repo_integration_changes.py` - Write manifest after applying changes
2. `demo-final-showcase.sh` - Read manifest instead of globbing
3. New file: `.integration_manifest.json` in target repo

**Manifest Format:**
```json
{
  "run_id": "abc123",
  "provider_code": "openai-chat",
  "timestamp": "2025-01-20T12:00:00Z",
  "files": [
    {"path": "src/integrations/clients/openai_chat.py", "action": "created"},
    {"path": "tests/integrations/test_openai_chat.py", "action": "created"}
  ]
}
```

**Pros:**
- Simple, explicit
- Works with any validation tool
- Easy to audit
- Already have `applied_changes` list

**Cons:**
- Extra file to manage
- Must clean up old manifests

**Complexity:** Low

---

### Option B: Git-Based (New Files Since Baseline)

**Approach:** Use `git diff --name-only HEAD~1` to find files changed in current run.

**Touch Points:**
1. `demo-final-showcase.sh` - Use git diff instead of glob

**Pros:**
- No extra files
- Git-native

**Cons:**
- Requires clean git state
- Fails if multiple runs without commits
- Complex if run spans multiple commits
- Target repo must be git-initialized

**Complexity:** Medium

---

### Option C: Workspace Isolation

**Approach:** Per-spec validation runs in a fresh temp directory, only generated files copied in.

**Touch Points:**
1. `demo-final-showcase.sh` - Create temp dir, copy only from applied_changes

**Pros:**
- Complete isolation
- No pollution possible

**Cons:**
- Copies files (I/O overhead)
- Loses context of target repo structure
- Import paths may break without proper setup

**Complexity:** Medium-High

---

### Option D: Hybrid (Manifest + Workspace)

**Approach:** Write manifest, validation creates isolated workspace from manifest.

**Touch Points:**
1. `apply_repo_integration_changes.py` - Write manifest
2. `demo-final-showcase.sh` - Read manifest, create isolated workspace

**Pros:**
- Best isolation
- Auditable via manifest

**Cons:**
- Most complex
- Overkill for current needs

**Complexity:** High

## Chosen Approach: Option A (Manifest File)

### Rationale

1. **Already have the data:** `state.plan["applied_changes"]` contains exactly the file list needed
2. **Minimal changes:** Only 2 touch points (write manifest, read manifest)
3. **Auditable:** Manifest file provides clear record of what was generated
4. **Simple:** No git dependencies, no file copying, no complex isolation

### Implementation Overview

#### Step 1: Write Manifest After File Writes

**File:** `apply_repo_integration_changes.py`

After writing files, create `.integration_manifest.json`:

```python
import json
from datetime import datetime

# After line ~390 where applied_changes is populated:
manifest = {
    "run_id": state.run_id,
    "provider_code": state.provider_code,
    "timestamp": datetime.utcnow().isoformat() + "Z",
    "files": [
        {"path": change["path"], "action": change["action"]}
        for change in applied_changes
        if not change.get("auto_generated")  # Skip __init__.py, pyproject.toml
    ],
}

manifest_path = repo_root / ".integration_manifest.json"
with open(manifest_path, "w") as f:
    json.dump(manifest, f, indent=2)
logger.info(f"Wrote integration manifest: {manifest_path}")
```

#### Step 2: Read Manifest in Per-Spec Validation

**File:** `scripts/demo-final-showcase.sh`

Replace glob-based collection with manifest reading:

```python
import json

manifest_path = os.path.join(repo_root, ".integration_manifest.json")
if not os.path.exists(manifest_path):
    print("   ⚠️  No integration manifest found - skipping validation")
    sys.exit(0)

with open(manifest_path, "r") as f:
    manifest = json.load(f)

print(f"   📋 Manifest: run_id={manifest['run_id']}, files={len(manifest['files'])}")

artifacts = []
for file_info in manifest["files"]:
    file_path = os.path.join(repo_root, file_info["path"])
    if os.path.exists(file_path) and file_path.endswith(".py"):
        try:
            with open(file_path, "r") as f:
                content = f.read()
            artifacts.append(ArtifactFile(path=file_info["path"], content=content))
        except Exception as e:
            print(f"   ⚠️  Could not read {file_path}: {e}")

if not artifacts:
    print("   ⚠️  No Python artifacts in manifest - skipping validation")
    sys.exit(0)
```

#### Step 3: Update SANDBOX_REPORT.md

Add validated file list to report:

```python
# In sandbox report generation:
report_lines.append("\n## Validated Files\n")
for file_info in manifest["files"]:
    report_lines.append(f"- `{file_info['path']}` ({file_info['action']})")
```

## Manifest Schema

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "required": ["run_id", "provider_code", "timestamp", "files"],
  "properties": {
    "run_id": {
      "type": "string",
      "description": "Unique identifier for this workflow run"
    },
    "provider_code": {
      "type": "string",
      "description": "Provider code identifying the integration"
    },
    "timestamp": {
      "type": "string",
      "format": "date-time",
      "description": "ISO 8601 timestamp when files were written"
    },
    "files": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["path", "action"],
        "properties": {
          "path": {
            "type": "string",
            "description": "Relative path from repo root"
          },
          "action": {
            "type": "string",
            "enum": ["created", "updated", "deleted"]
          }
        }
      }
    }
  }
}
```

## Backward Compatibility

- If no manifest exists, per-spec validation logs warning and skips (no failure)
- Old behavior preserved via `--legacy-validation` flag (optional)
- Manifest is ignored by git (add to `.gitignore`)

---

## Testing Strategy

1. **Unit test:** Manifest is written with correct format
2. **Unit test:** Manifest contains only non-auto-generated files
3. **Integration test:** Per-spec validation reads manifest correctly
4. **E2E test:** Full demo run with dirty target repo still passes
