4. **Deep copy overhead** - LangGraph copies state between nodes; for 700MB+ states this is catastrophic

- User experience is severely degraded

## Root Cause Analysis: Why 0% Success Rate in v6?

### Primary Cause Chain
```
Large spec (Stripe, GitHub, Slack) 
  → State object grows to 700MB+
    → LangGraph deep copies 700MB per node transition
      → Node transitions take minutes instead of milliseconds
        → 3+ hour gaps between nodes
          → Global 3600s timeout exceeded
            → Run fails with GlobalTimeoutError
```

### Secondary Cause Chain (Memory)
```
Large spec + repo_snapshot loaded
  → RSS grows to 4GB+
    → Memory ceiling triggered (4096MB)
      → Graceful abort
        → Run marked as failed
          → No code generated
```

### Why v6 is Worse Than v5
1. **Full mode (15 specs)** vs quick mode (3 specs) - more opportunities for failure
2. **Each spec runs 3 times** (root, apps_service-a, packages_sdk-python) - 3x the failure surface
3. **Memory pressure accumulates** across runs - later runs hit ceiling faster
4. **State not cleared between specs** - previous run's data may persist
